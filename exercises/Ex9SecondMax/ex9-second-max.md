# Ex9 第二大的数 · 笔记
## 题目定义（定义 B）
数组中**严格**的第二大：去掉所有和最大值相等的重复项后，剩下的最大者。
- `{3, 1, 5, 5, 2}` → 去重后 {3,1,2,5} → 第二大是 **3**（不是 5）
- `{4, 4, 4}` → 去重后只剩 {4} → **不存在**第二大
- 数组长度 < 2 → 不存在
## 最终方案：空椅子法
两个擂主都初始化为 `Integer.MIN_VALUE`（占位值，“空椅子”），循环从 i=0 开始，**每个数都排队过两道关卡**：
```java
public static Integer findSecondMax(int[] arr) {
    if (arr.length < 2) return null;          // 校验层
    int max1 = Integer.MIN_VALUE;             // 空椅子，不是 arr[0]
    int max2 = Integer.MIN_VALUE;
    for (int i = 0; i < arr.length; i++) {    // 从 0 开始，没有免检通道
        if (arr[i] > max1) {
            max2 = max1;                      // 旧擂主降级
            max1 = arr[i];
        } else if (arr[i] > max2) {
            max2 = arr[i];
        }
    }
    return (max2 == Integer.MIN_VALUE) ? null : max2;  // 判据只看 max2
}
```
打印提示的活儿在 main（调用方）里做，方法只管算，返回 `Integer`。
## 三颗雷（都是自己踩出来的）
### 雷一：免检初始化 → 重复冠军占死第二把椅子
**错法**：`max1 = arr[0]; max2 = arr[1];` 开局两数直接上擂，不排队。
**炸例**：`{5, 5, 3}`——开局 max1 = max2 = 5，第二把椅子坐的是冠军复制品。循环里 3 想进来：挤人条件 `3 > max2` 即 `3 > 5`，进不去。最后判“不存在”，但答案明明是 3。`{7,7,7,3}` 同款。
**规则**：
> 开局免检 = 拆护城河。任何值想上擂，必须和所有人一样过同一道关卡。占位值（MIN_VALUE）本身坐不进任何椅子，因为它过不了 `>` 这关。
### 雷二：收尾判据看错了对象
**错法**：用 `max1 == max2` 判“不存在”。那是双真值初始化时代的判据。
**炸例**：`{4, 4}`——两个 4 全被关卡挡在 max2 外（第一关 `4 > 4` 不成立，第二关 `max1 > 4` 不成立），max2 停在 MIN_VALUE。但 `max1 == max2` 即 `4 == MIN` 不成立 → 无声返回 -2147483648。
**规则**：
> 空椅子法判“不存在”，只看第二把椅子空不空：`max2 == Integer.MIN_VALUE`。max1 永远会坐上人（只要数组非空），看它没用。
### 雷三：错误码 -1 和合法答案撞车
**错法**：用返回 -1 表示“不存在”。
**炸例**：`{5, -1, -1}`——答案就是 -1。调用方拿到 -1，分不清是答案还是错误码。int 的每一个值都可能是某个数组的合法答案，**“挑一个冷门值当错误码”这条路在 int 里根本走不通**。
**规则**：
> 当所有合法值都可能成为答案时，错误信号必须来自类型本身给不了的那个状态。`Integer`（包装类）比 int 多一个 null——“没有这个值”，天然免疫撞车。更工程化的做法是抛异常（后面学）。
## 测试表（12 组，全绿）
| 数组 | 预期 | 验的是什么 |
|---|---|---|
| {3,1,4,1,5} | 4 | 常规 |
| {7,7,7} | 不存在 | 全重复 |
| {9,5,3,1} | 5 | 降序 |
| {-5,-2,-9} | -5 | **负数** |
| {8} | 不存在 | 校验层 |
| {8,3} | 3 | 双元素 |
| {4,4} | 不存在 | **雷二** |
| {3,9} | 3 | 双元素升 |
| {1,4,5} | 4 | 升序 |
| {5,5,3} | 3 | **雷一** |
| {5,-1,-1} | -1 | **雷三（-1 是答案）** |
| {7,7,7,3} | 3 | **雷一第二发** |
**教训**：自己换的测试数据恰好全部绕开了三颗雷。测试数据要**对着边界设计**，不是随手编——撞不上坑 ≠ 代码没坑。
## 带走的通用规则
1. 初始化占位值（哨兵值）后，所有数据必须统一入口，不留免检通道
2. 判据跟着方案走：换了初始化方式，“不存在”的判定条件也要跟着换
3. 错误码不能落在合法答案的取值域里；躲不开就换类型（null / 异常）
4. 方法只算数，打印交给调用方
5. 测试用例 = 常规 + 边界 + 专杀自己 bug 的那几发
