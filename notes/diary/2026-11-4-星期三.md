## 本课目标
把"执行一次就死"的 HelloAgent 改造成"活在循环里"的 Agent：
感知输入 → 决策 → 行动 → 再感知，直到收到退出信号。

## 一、三个设计问题的答案（决策记录）

### 1. 循环条件：`while(true)` + break，还是 `boolean running`？
**选择：`boolean running` 变量控制。**

理由：
- `while(true) + break` 同样能正常退出，程序行为没区别。
- 但 `boolean running` 让**循环条件本身**就说明了"Agent 在什么情况下活着"，
  退出逻辑不用翻遍整个函数去找 `break`。控制流可读性更好。

> 🔲 用你自己的话补充：如果团队里有人改代码，`while(true)` 和 `while(running)`
> 哪种更容易让人一眼看出退出点在哪？

### 2. 字符串判等：`==` 还是 `equals()`？大写输入退不退出？
**选择：`equals()` + 输入统一 `toLowerCase()` 后再比较。**

理由：
- `==` 比较的是引用，`equals()` 比较的是内容，判命令必须用 `equals()`。
- 决定让大写 `QUIT` 也能退出 → 所以输入先统一转小写。
- **关键一致性**：既然转了小写，那 `hello`、`time`、`status` 所有命令的判断
  都必须基于转换后的字符串，不能只对 quit 转、其他拿原始输入比。
  不一致就是 bug 温床。

> 🔲 你当初第二题说"把所有退出转成大小写相同的字符"——现在再想一遍，
> 为什么必须全局统一转换，而不是只处理 quit 那一个分支？

### 3. 前后空格 / 纯空格输入怎么处理？
**选择：`trim()` 去首尾空格。**

- `" hello "` → `"hello"`
- `"  "`（纯空格）→ `""`（空字符串）
- 空串会落到 `switch` 的 `case ""` 分支（我单独给空输入设计了分流），
  不计数、输出 `Nothing`。

> 🔲 这里我在 switch 里加了 `case ""` 专门接空输入和纯空格。
> 想想：如果不加这个 case，空输入会落到 default，被算成"一条命令"，对不对？

## 二、踩坑记录

### 坑 1：源码改了，JVM 却说找不到 main —— "三态不同步"灵异事件
**现象**：代码里明明有 `main`，运行报"找不到 main 方法"。
**原因**：VS Code 里文件没保存（标签页有白点●），跑的是上一次编译出的旧 `.class`。
**教训**：Java 跑的是**编译后的 .class**，不是正在编辑的源码。
编辑区 → 源文件 → class 文件，也是"三态"，和 git 三态一个思维。
源码改了必须保存 → 重新编译，才生效。

### 坑 2：`System.err` 不是"系统输出"
`System.err.println` 是错误输出流，终端里显示红色。
普通提示（欢迎语、命令反馈）一律用 `System.out`。
`err` 留给真正的错误——以后 Agent 排查日志时，两个流要区分开。

### 坑 3：`status` 自计数问题
原写法：
```java
case "status":
    status++;                        // 先把自己 +1
    System.out.println(... status ...);  // 再报告
```
结果：输入 hello、time 后查 status，报的是 **3**——把 status 自己也数进去了。

### 坑 4：字符串拼接丢空格
`"i have deal with " + status + " command(s)"` 一开始拼成了
`i have deal with3command(s)`。数字两边没有空格。
拼接时每一段前后都留好空格，对外输出观感会真实受影响。

### 坑 5：双分号、拼写错误
- `import java.util.Date;;` → 双分号，编译能过但是坏习惯。
- `"i dont kown"` → 拼写错误（know），Agent 面向用户的输出，会真实丢人。

### 坑 6：时间 API 新旧两代
`SimpleDateFormat + Date` 是 2014 年以前的旧 API。
现代写法是 `java.time`：`LocalDateTime.now()` + `DateTimeFormatter.ofPattern(...)`。
> 🔲 这个你还没实际改，下次可以两条都跑一遍对比。

## 四、设计立场：status 到底算不算一条命令？

**我的立场：算。** status 也是一次真实交互，计入总数。

依据：`hello → time → time → Status → quit`，最后 status 报 5，
数字和"每一次输入交互"对得上。

> 🔲 这条你必须自己表态：另一派观点是"用户只关心有效命令数，查询类不该计"。
> 你选哪个都行，但要能说清为什么——不能是"顺手写成这样"。

Agent 的骨架 = 循环 + 分发 + 防御 + 状态。
